# 道路設計の知識ベース（インプット 2026-07-07）

出典: 国交省 道路構造令解説 / 都市計画道路の考え方（詳細リンクはチャットログ参照）

## 4つの柱
1. **設計速度が全てを決める**: 速度→最小曲線半径・最大縦断勾配・車線幅・視距が自動的に決まる
   - 80km/h: 半径280m・勾配4-6%・車線3.5m ／ 40km/h: 半径60m・勾配7-9%
2. **道路の階層**: 自動車専用道路→幹線街路→補助幹線→区画街路。家は幹線に直接面させない。上位ほど交差点を減らす
3. **横断構成**: 車道+路肩+歩道+植樹帯のレイヤー。格が高いほど断面がリッチ
4. **道路が街区を作る**: 網目80-120mのブロックが土地利用を決める。道路は都市の骨格

## 標示・付帯物（実物準拠で実装済み）
- 中央線は幅5.5m以上の道路のみ。対面通行の高速はワイヤーロープ式防護柵（暫定2車線標準）✅
- 車道外側線=白実線15-20cm ✅ / 車線境界線=白破線 ✅
- 横断歩道: バー長3m・幅45cm・間隔45cm、バーは進行方向に平行 ✅（交差点に自動描画）
- 停止線: 幅30cm・左側車線・横断歩道の手前 ✅
- 導流帯（ゼブラ）: **現場の縁線から生成するくさび形の島**（形はテクスチャでなくジオメトリが持つ）✅ / 視線誘導標（夜発光）✅
  - 学び(2026-07-07): 固定サイズの三角テクスチャを置くと「貼り紙」になる。導流帯は本線縁線とランプ縁線の間に**開いていく隙間そのもの**。だから縁線2本から張る(wedgeGeo)
  - 出口のノーズ緩衝クッションは**塗装の下流=太い端**（舗装が物理的に割れる位置）。合流は逆に上流端。並走降下型(南IC)は壁の切り始めを守る位置
  - ゴア手前は破線→実線。レール(ランプ内側)はノーズから先だけ=塗装領域を貫かない
  - 塗りのバーは進行方向に直交させる（くさび先端のUV圧縮で斜線は潰れてモアレになる）

## ゲーム世界のスケール方針
- 世界は現実の約1/5圧縮。勾配・長さは「体感の実基準」に換算して1/2〜1/3で表現する
- ランプ勾配: 実基準7-9% → ゲームでは15%（直結ランプ）/ 9%（ループは実基準相当）

## トランペットIC（2026-07-07 ユーザー選択A → v1.2 東ループ追加）
- 北IC降りランプ: **東ループ式（半径9m・270°・勾配約9%）**。減速車線を7m北へ移設し、取り付きから南向きのまま左旋回→ループ南点に進入→東・北を回って西点で「南向き」に着地→側帯道路へそのまま合流。**進行方向が一度も反転しない一筆書き**
- 南IC降りランプ: 直線52m・勾配約10%のまま（ユーザー指定「2つのうち1つだけループ、もう1つは直線でいい」）
- ループはリボン曲面(BufferGeometry)でカクカク解消。ゼブラは境界線上の分岐直前へ+ノーズに緩衝クッション。出口予告板の柱は地面から
- 上りランプ: 西側に**ループ（半径11m・270°旋回・勾配約9%）**→ 高架の側道橋で北上→加速車線に合流
- 高架下通路の上を側道橋が立体交差（本物のトランペットICと同じ構図）
- ループの敷地は丘・森の生成マスクで平地化。東ループは街区の北の空き地(z<-80)に収め、舗装+レールが建設グリッドに一切かからない

## 大原則（2026-07-08 カクカク根絶パスで確立）
**道路の構成要素（路面・桁・縁線・レール・ロープ・導流帯）はすべて「点列（スプライン）から連続生成」する。**
直方体を回転して並べる方式は、角度・勾配が変わる継ぎ目で必ず重なりか隙間が出るため全廃した。
- 本線: 中心線HWXを2m間隔でサンプル → 路面リボン+箱桁リボン+外側線リボン+ワイヤーロープリボン
- 加減速車線+テーパー+取り付き: 本線の縁から膨らむ1枚のくさび(wedgeGeo)
- 坂・カーブ・側道橋・渡り線: 経路点列からのリボン(ribbonGeo)
- 監査: 箱型レール(RAILS)とリボン型レール(RAILPL=中心点列)の両方をrailAuditが照合する

## RoadNet生成層（2026-07-08 ユーザー発案「システム構築から」で導入）
Cities:Skylines式:「中心線×断面プロファイル」からランプ・橋の全部品を一括生成する`rnRoad(class, pts, opt)`。
- 生成されるもの: 路面(幅すり付け対応)+箱桁+両側縁線+**一体型高欄(パラペット)**+継ぎ目(弧長12m毎)+橋脚(弧長9m毎・等間隔・回避矩形対応)
- 高欄は自動でRAILPL(監査簿)に登録。区間指定(ノーズから/島の手前まで)もオプションで宣言
- 適用済み: 南IC坂・東ループ・西上りループ・側道橋+渡り線。**個別の板・レールの手置きは禁止**
- 完成イメージの北極星: ユーザー提供の多層IC参考画像(一体型高欄+等間隔橋脚+継ぎ目のクリーンな造形)
- 次段階: 定義層(セグメント+接続の宣言リスト)とnetAudit(端点一致・幅接続の機械検査)

## 設計原則（2026-07-07 東ループ失敗から学んだこと）
- **導線は「進行方向が反転しない一筆書き」で先に描く**。ループの中心をどこに置くかは、車の進入向きと退出向きの接線から逆算する（見た目の空き地に置いてから道を繋ぐと反転・貫通が生まれる）
- **見た目のリボンと走行経路は同じ点列(loopPts)を共有する**。二重定義はいつか必ずズレる
- 減速車線の位置は固定ではなく、ランプの幾何が必要とする助走から逆算して動かしてよい（動かしたら防音壁の切れ目・ゼブラ・ノーズ・出口予告板・本線直線契約z∈[-120,+52]も一緒に動かす）

## 竣工検査プロトコル（2026-07-07 ユーザー指示で標準工程化）
道路・構造物を建築/変更したら、報告前に必ず実施する:
1. **接続部・端部・レール端を1か所ずつ近接撮影**（__dbg.camで定点撮影: 分流部/坂の下端/ループ出入口/合流部/中央帯）
2. チェック観点は「システムが動くか」ではなく **「本物の道路として見えるか」**:
   - 路面同士が離れていないか・浮いていないか
   - レール/壁が途切れる・貫通する・二重になる箇所がないか
   - 標識の柱が地面から生えているか
   - 標示(ゼブラ/破線/停止線)の並び順が実物の文法どおりか
3. 見つけた粗は報告前に修正。修正後に再撮影して確認

## ガードレール導線監査（2026-07-07 ユーザー指摘で導入）
- **なぜレール事故が起きていたか**: レールを「見た目の穴埋め」で個別配置し、車の走行経路と突き合わせるチェックが無かった。
  発覚した実害: ①取り付き北縁レールが減速車線からの進入路を塞いでいた ②北ICの側道橋・ループの走行ラインが南ICの加速車線設備を貫通(IC同士の敷地干渉)
- **対策1: 機械監査** `__dbg.railAudit()` — 全レール(wall材)×全走行経路(RAMP_PATHS)の交差を自動検出。道路工事のたびに実行し0件を確認する
- **対策2: 南ICを出口専用ハーフICに** — IC間隔56mにフルIC2基は実物でもあり得ない。上り入口は北のマイシティICに集約(実在の都市高速と同じ構成)
- **ルール: レールを新設・移動したら必ずrailAudit→0件→竣工検査撮影→報告**
